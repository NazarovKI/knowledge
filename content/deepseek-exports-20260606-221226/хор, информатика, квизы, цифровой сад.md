DeepSeek: Отличный и очень актуальный вопрос. В России наблюдается значительный рост интереса к открытому ПО (Open Source), в первую очередь из-за политики импортозамещения и ухода с рынка зарубежных вендоров.

Переход редко бывает полным на 100%, но многие компании и госструктуры активно внедряют связку **Linux + LibreOffice + другие open-source решения**.

Вот основные категории и конкретные примеры компаний и организаций, которые публично заявляли о переходе или массовом внедрении:

### 1. Крупнейшие государственные и окологосударственные компании

Именно здесь происходит самый массовый и централизованный переход.

*   **Почта России**: Одна из самых известных историй. Компания массово переводит рабочие места на ОС **Astra Linux** (российский дистрибутив на базе Debian) и офисный пакет **Р7-Офис** (форк LibreOffice) / **МойОфис**. Это десятки тысяч рабочих мест.
*   **Сбербанк**: Активно развивает собственную экосистему на основе Linux. Они не только используют, но и разрабатывают свои дистрибутивы (например, **SLES** от SberTech), перевели большую часть серверной инфраструктуры на Open Source, внедряют LibreOffice/Р7-Офис на рабочих местах.
*   **Ростелеком**: Использует российские дистрибутивы Linux (Astra, RED OS) и офисные пакеты на базе LibreOffice. Как интегратор, они также продвигают эти решения среди своих клиентов.
*   **РЖД**: Проводит пилотные проекты по переводу рабочих мест на ОС Astra Linux и отечественные офисные пакеты.

### 2. IT-компании и разработчики

Для них использование Open Source — это естественная среда.

*   **Яндекс**: Известен своей масштабной использованием Linux по всей инфраструктуре. Хотя на рабочих местах разработчиков тоже часто стоит Linux или macOS, они являются крупными контрибьюторами в открытые проекты.
*   **Лаборатория Касперского**: Долгие годы использует Linux на серверах и для части рабочих мест. Разрабатывают и собственные решения для защиты ОС Linux.
*   **VK (ранее Mail.ru Group)**: Активно используют Linux в своей серверной и облачной инфраструктуре.
*   **Astra Linux (РусБИТех-А)**, **RED OS**, **BaseALT**, **РОСА**: Это сами разработчики российских дистрибутивов Linux. Естественно, вся их внутренняя инфраструктура построена на их же продуктах и LibreOffice.

### 3. Образовательные и научные учреждения

*   **Вузы и школы**: Многие учебные заведения (например, Южно-Уральский государственный университет, МГУ и др.) переводят компьютерные классы на Linux (чаще всего ALT Linux или Astra Linux) для обучения, чтобы сэкономить на лицензиях и привить студентам навыки работы со свободным ПО.
*   **Академия наук РФ**: Научные институты исторически широко используют Linux для вычислений и моделирования.

### 4. Телекоммуникационные и промышленные компании

*   **Транснефть**, **Газпром**: Начинают внедрять российское ПО на критически важных объектах, что включает серверные ОС Linux. Перевод рабочих мест идет более медленными темпами, но пилотные проекты есть.
*   **Крупные региональные телеком-операторы**: Постепенно внедряют российские ОС и офисные пакеты в рамках выполнения требований регуляторов.

### Ключевые моменты, которые важно понимать:

1.  **Не всегда "чистый" Linux**: Часто используются **российские дистрибутивы** (Astra Linux, RED OS, ALT Linux), которые основаны на ядре Linux, но прошли сертификацию ФСТЭК и Минобороны, что является важным требованием для госсектора.
2.  **Не всегда LibreOffice "из коробки"**: Часто используется **Р7-Офис** или **МойОфис**. Это коммерческие продукты, но они являются **форками (ответвлениями) LibreOffice** с дополнительным набором функций, поддержкой и интеграцией с отечественным ПО. По сути, это то же открытое ядро.
3.  **Поэтапный переход**: Полный отказ от Windows/Microsoft Office — сложный процесс. Чаще всего переход идет поэтапно: сначала на серверы, затем на рабочие места непрофильных сотрудников, и в последнюю очередь — на места, требующие узкоспециализированного ПО.
4.  **Драйвер — импортозамещение**: Главным драйвером является не столько философия Open Source, сколько государственная политика в области импортозамещения и кибербезопасности (Постановление Правительства № 1236, 2015 г.).

DeepSeek: Отличный вопрос! В зависимости от контекста, у слова **«стек»** есть два основных значения, которые часто используются в IT и не только. Давайте разберем оба.

### 1. Стек (структура данных)

Это фундаментальное понятие в компьютерных науках.

**Простое объяснение:**
Представьте себе стопку (стек) тарелок. Вы можете добавить новую тарелку только сверху. И взять можно тоже только верхнюю тарелку. Вы не можете вытащить тарелку из середины, не свалив всю стопку.

**Принцип работы:** LIFO (Last In, First Out) — **«Последним пришел, первым ушел»**.

**Основные операции:**
*   **Push** — добавить элемент на вершину стека. (Положить тарелку сверху).
*   **Pop** — удалить и вернуть верхний элемент стека. (Взять верхнюю тарелку).
*   **Peek (или Top)** — посмотреть на верхний элемент, не удаляя его.

**Где используется?**
*   **Отслеживание вызовов функций:** Когда программа вызывает функцию, информация о ней (возвращаемый адрес, локальные переменные) помещается в стек. Когда функция завершается, эта информация извлекается.
*   **Отмена действий (Ctrl+Z):** Ваши действия в текстовом редакторе сохраняются в стек. Нажатие Ctrl+Z извлекает последнее действие из стека.
*   **Парсинг выражений:** Проверка корректности расстановки скобок `((a+b) * c)`.

---

### 2. Стек технологий (Tech Stack)

Это самое частое значение, которое вы услышите в IT-компаниях, в том числе и в РЖД, о которых мы говорили ранее.

**Простое объяснение:**
Это **набор технологий, инструментов, языков программирования и сервисов**, которые используются для создания и работы одного приложения или целой IT-инфраструктуры компании.

Представьте, что вы строите дом. Ваш «стек» будет включать:
*   **Фундамент** -> Операционная система (например, Linux)
*   **Каркас и стены** -> Серверное ПО (например, Nginx), язык программирования (например, Python)
*   **Коммуникации** -> База данных (например, PostgreSQL)
*   **Отделка и интерьер** -> Frontend-фреймворк (например, React)

**Основные компоненты стека:**

1.  **Frontend (клиентская сторона)** — то, что видит и с чем взаимодействует пользователь в браузере.
    *   *Языки:* HTML, CSS, JavaScript.
    *   *Фреймворки/библиотеки:* React, Angular, Vue.js.

2.  **Backend (серверная сторона)** — то, что работает на сервере, обрабатывает логику, работает с данными.
    *   *Языки:* Java, Python, C#, Go, PHP, Node.js.
    *   *Фреймворки:* Spring (для Java), Django (для Python), .NET (для C#).
    *   *Серверы:* Nginx, Apache.

3.  **База данных (Data Storage)** — где хранится информация.
    *   *Реляционные (SQL):* PostgreSQL, MySQL, Oracle.
    *   *Нереляционные (NoSQL):* MongoDB, Redis, Cassandra.

4.  **Инфраструктура (Infrastructure)** — как приложение развернуто и масштабируется.
    *   *Облака:* Yandex Cloud, SberCloud, AWS, Azure.
    *   *Контейнеризация:* Docker, Kubernetes.
    *   *Операционные системы:* Linux (Ubuntu, CentOS, Astra Linux).

**Примеры популярных стеков:**

*   **LAMP Stack:** **L**inux (ОС) + **A**pache (сервер) + **M**ySQL (БД) + **P**HP (язык). Классический стек для веб-разработки.
*   **MEAN Stack:** **M**ongoDB (БД) + **E**xpress.js (бэкенд-фреймворк) + **A**ngular (фронтенд-фреймворк) + **N**ode.js (бэкенд-платформа). Полностью на JavaScript.
*   **Стек, который может использовать РЖД (условный пример):**
    *   **Backend:** Java + Spring Framework
    *   **Frontend:** React + TypeScript
    *   **База данных:** Oracle + PostgreSQL
    *   **Сервер ОС:** **Astra Linux** (российский дистрибутив)
    *   **Офисное ПО:** **Р7-Офис** (на базе LibreOffice)

### Резюме

*   **Стек (структура данных)** — это абстрактный тип данных, работающий по принципу LIFO.
*   **Стек технологий** — это комплекс инструментов, которые разработчик или компания используют для создания проекта.

Когда на собеседовании спрашивают: «Каким стеком вы владеете?» — имеют в виду второй вариант.

DeepSeek: Отличный вопрос! **Confluence** и **GitBook** — это две популярные платформы для создания, хранения и совместной работы над документацией. Они помогают структурировать знания в командах и компаниях.

Несмотря на схожие цели, у них разная философия и целевая аудитория. Давайте разберем каждую.

### Confluence

**Простыми словами:** Это **«Википедия для вашей компании»** или мощная **цифровая библиотека и рабочее пространство** для команды.

**Ключевые характеристики:**

*   **Производитель:** Компания **Atlassian** (та же, что делает Jira, Trello).
*   **Модель распространения:** Часто используется как корпоративный портал внутри организации.
*   **Философия:** Создание связанного, живого пространства знаний. Отлично подходит для самого разного контента — от технических спецификаций до протоколов встреч и описания бизнес-процессов.
*   **Основные функции:**
    *   **Иерархия страниц и пространств (Spaces):** Можно создавать отдельные пространства для каждого отдела (например, "Пространство IT", "Пространство Маркетинга").
    *   **Богатое редактирование:** Очень мощный редактор, похожий на Word. Можно вставлять таблицы, диаграммы, изображения, видео, код.
    *   **Глубокая интеграция с Jira:** Самое сильное преимущество. Можно вставлять на страницы списки задач, диаграммы из Jira, автоматически обновляемые дашборды.
    *   **Шаблоны:** Огромное количество готовых шаблонов для встреч, требований, спецификаций, планов работ.
    *   **Комментарии и упоминания:** Полноценные инструменты для обсуждения прямо на странице.

**Кто использует?**
Крупные и средние компании, где важны процессы и централизация знаний. Например, отделы **разработки (для техдокументации)**, **маркетинга**, **HR (для onboarding новых сотрудников)**, **менеджеры проектов**.

**Аналог из жизни:** Общая папка с документами в компании, но не просто файлы, а взаимосвязанные веб-страницы с мощным поиском.

---

### GitBook

**Простыми словами:** Это **элегантная и современная платформа для создания публичной и приватной документации к продуктам, API и сервисам**.

**Ключевые характеристики:**

*   **Производитель:** Независимая компания GitBook.
*   **Модель распространения:** Популярен среди разработчиков и стартапов. Часто используется для документации, которая будет доступна пользователям снаружи.
*   **Философия:** Простота, чистота и фокус на читательском опыте. Документация выглядит стильно и современно "из коробки".
*   **Основные функции:**
    *   **Древовидная структура:** Очень четкое и понятное оглавление (table of contents) слева.
    *   **Чистый и минималистичный редактор:** Часто с поддержку Markdown, что очень нравится разработчикам.
    *   **Интеграция с Git:** Можно синхронизировать контент с репозиторием GitHub/GitLab, что позволяет использовать привычный workflow с коммитами и пулл-реквестами.
    *   **Красивые публичные страницы:** Созданная документация автоматически выглядит как у современных IT-продуктов (например, как документация Stripe или Slack API).
    *   **Версионирование:** Можно вести несколько версий документации (например, для v1 и v2 вашего API).

**Кто использует?**
Разработчики, стартапы, продуктовые команды для создания:
*   **Публичной документации для пользователей**
*   **Документации по API**
*   **Внутренней базы знаний**, где важна простота и красота

**Аналог из жизни:** Красиво изданное руководство пользователя для вашего программного продукта, которое всегда доступно онлайн.

    *   Рисую на доске таблицу разрядов для двоичного числа 1101₂:

| Разряд (n) | 3   | 2   | 1   | 0   |
|------------|-----|-----|-----|-----|
| Степень 2ⁿ | 2³  | 2²  | 2¹  | 2⁰  |
| Значение   | 8   | 4   | 2   | 1   |
| Цифра числа| 1   | 1   | 0   | 1   |

*   **Алгоритмизация (создаем опору):**
    *   Проговариваем и записываем в тетради **алгоритм**:
        1.  Пронумеровать разряды числа справа налево, начиная с нуля.
        2.  Записать сумму произведений каждой цифры на основание системы (2) в степени ее разряда.
        3.  Вычислить полученную сумму в десятичной системе.
    *   **Формула:** `N₁₀ = d*2ⁿ + ... + d*2¹ + d*2⁰`

*   **(Техника «Правильно — значит правильно»)** Разбираем пример 1101₂:

    *   «Верно: 1*8 + 1*4 + 0*2 + 1*1 = 8 + 4 + 0 + 1 = 13. Значит, 1101₂ = 13₁₀».

1.  **Создать вебхук в Bitrix24**: В разделе «Разработчикам» создайте новый «Входящий вебхук». В настройках прав обязательно выдайте права как минимум к **CRM** [citation:2][citation:9].
2.  **Скопировать URL вебхука**: После сохранения вы получите уникальный URL, который нужно скопировать [citation:1][citation:10].
3.  **Настроить интеграцию в конструкторе**: В личном кабинете сервиса квизов (например, Marquiz [citation:1] или Moсlients [citation:6]) найдите настройки интеграции с Bitrix24 и вставьте скопированный URL вебхука.
4.  **Назначить ответственного и воронку**: В настройках интеграции укажите, на какого сотрудника будут назначаться заявки и в какую воронку сделок они должны попадать [citation:2].

### 💡 Рекомендации по выбору и внедрению

-   **Для простоты и скорости**: Если вам нужен классический квиз-опрос и вы хотите максимально быстро начать работу, выбирайте между **готовым модулем из Маркетплейса** [citation:4] или **конструктором Moсlients** [citation:6].
-   **Для точного расчета стоимости**: Если главная цель — дать клиенту точный предварительный расчет цены на окна или балкон, оптимальным решением будет **специализированный оконный калькулятор** [citation:8].
-   **Проверка интеграции**: После настройки обязательно протестируйте квиз: заполните его сами и проверьте, создается ли сделка в Bitrix24, и корректно ли передаются все данные [citation:2][citation:9].

## 🔧 Пошаговое решение

### 1. **Активируйте GitHub Pages в настройках репозитория**

Перейдите по ссылке из ошибки:
```
https://github.com/NazarovKI/veka/settings/pages
```

И настройте:
- **Source**: Deploy from a branch
- **Branch**: `main` или `gh-pages` (обычно `main`, корневая папка или `/docs`)

### 2. **Проверьте структуру проекта**

Убедитесь, что в вашем репозитории есть файлы для деплоя:
```
veka/
├── index.html          # Главная страница
├── styles/
│   └── style.css       # Стили
└── scripts/
    └── script.js       # Скрипты
```

### 3. **Настройте workflow файл**

Создайте/проверьте файл в репозитории:
```yaml
# .github/workflows/deploy.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      
      - name: Setup Pages
        uses: actions/configure-pages@v3
      
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v2
        with:
          path: '.'  # Или папка с вашими файлами (например 'dist')
      
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v2
```

### 4. **Альтернативные решения**

**Если используете статические файлы:**
```yaml
# Упрощенный workflow для статических файлов
name: Deploy Static Site

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/upload-pages-artifact@v2
        with:
          path: .
```

### 5. **Проверьте права доступа**

- Убедитесь, что GitHub Pages включен в настройках репозитория
- Проверьте, что у workflow есть права на запись
- Убедитесь, что ветка существует и в ней есть контент для деплоя

### 6. **Для проектов с сборкой**

Если у вас проект требует сборки (React, Vue, etc):
```yaml
name: Deploy React App

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 18
          
      - name: Install and build
        run: |
          npm install
          npm run build
          
      - name: Deploy
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./build  # или ./dist
```

## Перевод из двоичной в десятичную

### Алгоритм перевода:
1. Пронумеровать разряды справа налево (с 0)
2. Умножить каждую цифру на 2ⁿ (n - номер разряда)
3. Сложить результаты

### Пример: 1101₂
| Разряд | 3   | 2   | 1   | 0   |
|--------|-----|-----|-----|-----|
| 2ⁿ     | 2³=8 | 2²=4 | 2¹=2 | 2⁰=1 |
| Цифра  | 1   | 1   | 0   | 1   |
| Результат | 1×8=8 | 1×4=4 | 0×2=0 | 1×1=1 |

**1101₂ = 8 + 4 + 0 + 1 = 13₁₀**

## Перевод из десятичной в двоичную

### Алгоритм деления:
1. Делим число на 2
2. Записываем остаток (0 или 1)
3. Частное снова делим на 2
4. Повторяем, пока частное ≠ 0
5. Записываем остатки в обратном порядке

### Пример: 13₁₀ → ?₂
```
13 ÷ 2 = 6 (остаток 1)  ←
6 ÷ 2 = 3  (остаток 0)  ↑
3 ÷ 2 = 1  (остаток 1)  ↑  
1 ÷ 2 = 0  (остаток 1)  ↑
```
**13₁₀ = 1101₂**

import re
import os

def fix_wikilinks(text):
    # [[Link]] -> [[link]]
    text = re.sub(r'\[\[(.*?)\]\]', 
                 lambda x: f"[[{x.group(1).lower().replace(' ', '-')}]]", text)
    return text

for root, dirs, files in os.walk('content'):
    for file in files:
        if file.endswith('.md'):
            path = os.path.join(root, file)
            with open(path, 'r', encoding='utf-8') as f:
                content = f.read()
            
            new_content = fix_wikilinks(content)
            
            with open(path, 'w', encoding='utf-8') as f:
                f.write(new_content)

## ❌ 7. Решение частых проблем

### Если забыли настроить пользователя:
```bash
# Ошибка: Please tell me who you are
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
```

### Если изменился URL репозитория:
```bash
# Проверить текущий remote
git remote -v

# Изменить URL
git remote set-url origin git@github.com:username/new-repo.git
```

### Если есть конфликты при пуше:
```bash
# Сначала тянем изменения
git pull origin main

# Решаем конфликты, затем
git add .
git commit -m "Merge conflicts resolved"
git push origin main
```

### Если SSH не работает:
```bash
# Проверяем подключение
ssh -T git@github.com

# Перезапускаем SSH-агент
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

## 📋 8. Чек-лист для новичка

```bash
# 1. Настройка SSH
ssh-keygen -t ed25519 -C "email@example.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub | xclip -selection clipboard

# 2. Настройка Git
git config --global user.name "Your Name"
git config --global user.email "email@example.com"

# 3. Клонирование
git clone git@github.com:username/repo.git

# 4. Работа
cd repo
# редактируем файлы...
git add .
git commit -m "First commit"
git push origin main
```

Теперь у вас есть полная система для комфортной работы с Git и GitHub без постоянного ввода пароля! 🚀
